# 水浸管理 demo

**当前通信默认改为设备TCP CLIENT主动接入。** 请优先按照同目录 `water_alarm_gateway_DEPLOY.md` 部署常驻服务和环境配置；本文下方的192.168.0.80:123直连说明是保留的 `MODE=direct` 模式。现有设备记录不用重新添加，此次改造无新增SQL。

入口：小区后台 → 智能硬件 → 水浸管理 → 设备管理。

本版是声光报警器手动控制，不包含水浸传感器采集、自动报警联动或告警通知。

## 默认配置及操作

- 固定 TCP Server：192.168.0.80:123，Modbus 地址1。PHP服务端主动连接设备，发送带CRC的Modbus RTU报文，不使用Modbus TCP MBAP头。
- 添加设备只填写名称，不发送控制指令。名称可编辑。
- 当前仅一台物理设备，以IP、端口、地址全局唯一，避免多个小区或多条记录控制同一设备。后台客户端不能覆盖网络目标。
- 报警：功能码0x10，从地址1写入 `[设定音量, 0x0001, 0xFF01]`。默认音量1、爆闪、第一条语音持续循环，直到手动停止。
- 停止报警 / 状态未知时的停止声光：从地址2写入 `[0, 0]`。
- 启动仅闪光：从地址2写入 `[1, 0]`，同时停止声音。
- 停止闪光：地址2写入0，不修改声音；若报警仍在播放，报警按钮仍显示停止报警。
- 音量调整：功能码0x06写地址1，范围1至31，禁止0静音；读回设备实际档位（部分型号自动限制最高档位）。保存后作为下一次报警的设定值。
- 被动刷新不改变设备音量，也不把旧音量覆盖到报警设定。设备当前静音也仍以默认音量1启动报警。
- 不写掉电记忆寄存器。设备断电后行为遵从原设备设置，不保证恢复断电前报警。

## 结果及故障处理

- 按小区隔离设备、编辑和日志接口；操作人和角色写入日志。
- 使用MySQL `GET_LOCK` 对物理设备串行控制；忙时不排队重复触发。
- 每次操作建立短连接，完整写入指令；按长度读取分包，检查地址、功能码、CRC、异常码和写入回显；随后读回音量、灯光、曲目。
- 连接超时2秒，每个协议交换总超时2秒，前端请求30秒（TTS需要多条设置和状态查询）；不自动重试启动类指令。
- 未收到确认、读回不符或连接中断时标为结果未知。页面不会把失联理解为停止，提供停止声光按钮。
- 命令发送前先保存pending记录并清除可信状态；PHP异常退出后仍可检查未完成记录。
- 页面每10秒读状态，隐藏标签页、打开音量/文字播报弹窗及离开页面暂停轮询；超过20秒的快照不作为当前状态。关闭页面不会停止报警。
- 最近50条日志记录实际操作和结果，不记录轮询。数据库异常由ThinkPHP日志记录。

## TTS文字播报增量

设备操作区增加“文字播报”，打开弹窗后可添加单段文字、查看已保存列表、逐条点击“播报”。每个设备最多保存100条，列表分页展示；相同文字不重复保存。关闭弹窗不会停止设备，弹窗提供“停止播报”。这是文字转语音（TTS），不包含录音识别或语音转文字。

文字操作列支持“删除”，二次确认后删除数据库中的对应文字并刷新列表。删除按当前小区、设备及文字ID校验，不会停止设备正在进行的播报；历史播报日志保留内容快照。删除功能不需要新增SQL，更新控制器、服务及前端页面/API后重新构建即可。

### 协议与状态

- 从数据库按当前小区、设备、文字ID查找内容，不接受播报接口直接传入任意文本。
- 发送前停止TTS和普通曲目；设置 `0x001F=6` 使用UTF-8，`0x0022=设定音量`、`0x0023=1`。
- `0x10` 写入 `0x003D`，数据为 `0xFF + UTF-8文字`。FF表示持续循环。文本最多199字节（常见中文约66字），连同重播字节和补位最多200字节。
- 数据长度为奇数时在末尾补ASCII空格，避免使用协议示例中不一致的奇数字节报文；寄存器数严格为数据字节数/2。方括号和控制字符不允许输入，避免文本内标记绕过设定音量。
- TTS状态读 `0x0021`（0未初始化、1空闲、2运行中），音量、灯光读 `0x0022/0x0023`。设备列表的声音状态同时考虑普通曲目与TTS。
- 停止操作先向 `0x0020` 写1，再停止普通曲目并关灯；即使TTS停止失败仍尝试普通声光停止，但不报告完全停止成功。
- 音量同时写普通音量和TTS音量。停止闪光同时关闭TTS灯光模式及普通灯光，保留正在播放的声音。
- 发送文字后校验写入确认、读回TTS运行状态；未初始化、状态不符或超时均不报告成功。不会自动重复发送播报。
- 操作日志记录文字编号、文字快照及结果，按小区权限隔离。
