# 活动多人代报名

部署顺序：先运行 `php tools/install_social_activity_participants.php`，再发布后端接口及小程序。迁移仅新增参加人表，可重复执行；历史订单不做身份猜测或批量改写。

流程为当前房间参加人多选 → 一个场次及票种 → 确认每位参加人的资料 → 统一付款。每位参加人一张票，订单 `uid` 仍为付款人，`num` 由服务端根据人数计算。一个订单统一使用所选票种和一份活动报名表单，保持现有整单退款规则。

`api.ActivityOrder/participants` 接收 `activity_id`、`village_id`、`pigcms_id`，其中 `pigcms_id` 必须是登录人在当前房间的有效绑定记录。返回按业主、家属、租客等身份分组的人员及不可选状态。下单接口新增 `participants: [{bind_id, user_name, id_number}]`。姓名和身份证优先使用绑定记录；缺失时允许补填，不修改房间原始资料。

防重复以同一活动为范围，不因换场次、票种、房间或下单人而允许重复。待支付与已报名订单均占用名额；已取消订单释放名额。身份匹配使用绑定记录、账号及身份证，并兼容旧订单。写入时在事务内锁活动行，重新检查参加人、重复记录及库存，再原子保存订单和全部参加人。库存及支付复核均按票数求和。

“我的活动”和详情允许付款人及实际参加人访问。没有账号的参加人在同一绑定记录关联账号后也可看到报名。所有订单成员看到相同的完整报名名单和票券信息；只有订单创建人可以支付或申请退款，接口会校验创建人身份。个人扫码签到只核销自己的参加记录；任意一人签到后，订单不可整单退款。

本地回归：`php tools/test_social_activity_participants.php`。测试使用连接私有的 MySQL 临时表，退出即清除，不发起真实支付。覆盖多人免费/付费下单、跨账号可见性、鉴权、防重复、旧订单、库存、取消及个人签到。测试需存在基础用户、活动、场次等示例记录作为表结构兼容样本，以及一个正常小区。

上线前仍需在微信开发者工具中完成一次真实登录及支付沙箱联调。自动化测试未调用外部支付网关。

外部用户：参加人选择页可填写姓名、手机号、身份证号，三项必填。仅限业主场次不允许外部用户；添加外部用户后前端只显示允许的场次，服务端再次校验。外部用户使用手机号关联已有账号，未注册者后续用该手机号登录也可查看订单。外部记录的 bind_id 为 0，人员列表以 participant_id 区分。

更新时必须重新运行 install_social_activity_participants.php：增加 phone 字段，调整旧的 order_id+bind_id 唯一索引以支持同单多个外部用户，并添加身份证防重复索引。也可对上一版表结构一次性执行 social_activity_external_participants.sql。
