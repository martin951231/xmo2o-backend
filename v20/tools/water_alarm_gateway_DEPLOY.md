## 1 配置环境变量

在生产 `v20/.env` 中添加或合并以下段落，不要覆盖原数据库等配置：

```ini
[WATER_ALARM]
MODE = gateway
LISTEN_HOST = 0.0.0.0
LISTEN_PORT = 32986
CONTROL_PORT = 32987
GATEWAY_SECRET = "填写自行生成的64位随机密钥"
ALLOWED_PEERS = "填写设备现场当前的公网出口IPv4"
```

生成密钥（在服务器终端执行一次，生成后填入配置，不用填进设备）：

```bash
php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'
```

密钥至少32字符；Web/PHP-FPM和常驻命令必须使用同一套配置、在同一台服务器运行。内部控制端口固定仅绑定127.0.0.1，不需要也不要通过公网映射。设备端口与控制端口不能相同。

`ALLOWED_PEERS` 填**设备现场网络**的公网IPv4，不是 `192.168.0.80`，也不是服务器 `39.96.188.189`。可在现场同一路由器的电脑上查询“我的公网IP”；手机查询时关闭移动网络、使用现场Wi-Fi。允许填写多个明确IPv4，用英文逗号分隔。未填写或格式不正确时服务拒绝启动，不会默认接收任意来源。

**现场公网IP变更时：**修改 `ALLOWED_PEERS`，同步修改服务器安全组/防火墙中的来源限制，然后执行 `supervisorctl restart water-alarm-gateway`。配置在进程启动时加载，改文件后必须重启。设备会重新连接；服务不会自动重发之前失败的报警指令。

## 2 服务器端口

- 云服务器安全组、系统防火墙允许来自现场公网IP的 **TCP 32986**。
- `32987` 是进程内部控制端口，保持仅本机可访问，不开放公网。
- 32986是原始TCP端口，不是HTTP接口，不通过Nginx普通HTTP location转发。
- 同一个设备接入服务只运行一个进程，不要开启多个副本或多worker竞争连接。

当前厂家协议没有设备登录令牌或可验证的注册协议，所以本版以来源IPv4、型号读回和专用监听端口匹配**唯一一台报警器**，不声称这等同于设备级加密身份认证。同一现场公网IP下请只让这一台报警器连接32986。已有设备在线时，第二条连接会被拒绝，不能抢占。

## 3 启动和守护

先在服务器终端进入实际项目的 `v20` 目录，前台检查：

```bash
php think waterAlarmGateway
```

正常启动会显示设备监听端口和内部控制端口。设备接入并通过只读型号查询后，日志显示“设备在线”。退出前台检查后再启用Supervisor，不能让两个进程重复监听。

项目附带 `supervisor.conf/water-alarm-gateway.conf` 模板。根据生产环境修改：

- `directory`：实际项目的v20目录。
- `command`：服务器PHP CLI的绝对路径及 `think waterAlarmGateway`。
- `user`：站点运行用户，例如www，需能读取v20/.env。
- `stdout_logfile`：实际项目的 `v20/runtime/water-alarm-gateway.log`；目录需存在且运行用户可写。

将模板加入现有Supervisor配置后：

```bash
supervisorctl reread
supervisorctl update
supervisorctl status water-alarm-gateway
```

若机器未安装Supervisor，也可用已有进程守护工具，以相同命令和工作目录设置开机启动、退出自动重启；不能只依赖网页请求或定时任务保持TCP连接。

## 4 设备配置

| 字段 | 值 |
| --- | --- |
| 网络模式 | TCP CLIENT |
| 设备IP | 192.168.0.80，保持现场正确网段 |
| 网关、子网掩码 | 现场路由器对应参数 |
| 目的IP | 39.96.188.189 |
| 目的端口 | 32986 |
| 本地端口 | 保留设备原配置 |
| 内部串口参数 | 9600、8位、1停止位、无校验 |
| 自定义注册包/主动心跳包 | 如存在这些选项，请关闭；服务端用Modbus只读查询保活 |

保存后确认设备能够上网。现场断网或服务器重启后，网络模块需要主动重连；具体重连设置以厂家工具/固件为准。正常情况下会重新出现“设备在线”日志；若固件没有自动重连，则在恢复网络后重新连接或重启设备。

## 5 验收与故障定位

1. 查看接入日志，确认来源IP正确且出现设备在线/型号902或912。
2. 后台进入水浸管理，刷新状态。后台不是直接拨号到设备192.168.0.80。
3. 在现场有人确认的情况下，测试报警、停止、闪光、音量和TTS。
4. 断开设备网络后，后台操作应失败或显示结果未知；重新连接不会自动启动之前失败的报警。
5. 关闭网页或重启接入服务**不等于停止报警**；设备正在循环播报时，恢复连接后需要主动点击停止。

常见提示：

- “TCP接入服务未启动或不可用”：检查常驻进程及本机32987。
- “接入服务认证失败”：检查Web与命令行的GATEWAY_SECRET是否一致，更新配置后重启进程/按生产配置缓存流程刷新。
- “设备未连接生产服务器”：检查设备TCP CLIENT目标、现场上网、32986端口、ALLOWED_PEERS和安全组来源。
- “来源未放行或已有设备在线”：检查公网出口IP是否变化，或是否有第二台设备/旧连接占用。
- “收到非请求数据”：关闭厂家自定义注册包/心跳包。协议按纯Modbus RTU透传处理。
- CRC错误、超时或连接中断后：当前设备连接会被丢弃，等待设备重连，防止旧回复错误确认新命令。不会自动重试写指令。
- TTS状态0：表示设备报告未初始化，这是设备模块状态，与公网连接是否建立是两个问题。

## 验证范围
